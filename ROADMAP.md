# Roadmap

Из конкурентного разбора (Rose, Combot, CAS, Shieldy, KolasAI, SmartMod) — см. обсуждение в чате.
Порядок = приоритет.

## 1. Капча для новых участников — `готово`
Отраслевой стандарт (есть у Rose, Shieldy, SmartMod), у нас не было вообще.
**Выключена по умолчанию**, в Mini App убрана в свёрнутый раздел «Дополнительно»
(не на первом экране настроек, чтобы не перегружать базовый флоу).

- `captchaEnabled: boolean` (default `false`) в настройках группы
- При включении: новый участник мутится + получает кнопку-подтверждение
  «Я не бот» в группе (2 минуты). Не нажал вовремя — кик при следующем
  сообщении в группе (лениво, без отдельного воркера/крона — serverless-деплой
  без персистентного процесса, см. `lib/telegram/captcha.ts`)
- Чат-команда `/captcha on|off`
- Mini App: тумблер в свёрнутой секции «Дополнительно» (по умолчанию закрыта)
- Осведомлённость о правах бота (`missingPermissionsFor`) теперь учитывает
  и капчу — она тоже требует право «Блокировка участников»

## 2. Приветственные сообщения — `готово`
- `welcomeEnabled: boolean`, `welcomeMessage: string | null`
- Плейсхолдер `{user}` → HTML-упоминание нового участника
- Команда `/welcome <текст>` / `/welcome off`
- Поле ввода в Mini App (видимо на основном экране настроек, не спрятано)

## 3. Расширенная статистика (не только нарушения) — `готово`
- Новые счётчики за день: `messages`, `joins` (`lib/db/stats.ts` → `incrementActivity`/`getActivity`)
- Отдельная секция «Активность» на экране статистики Mini App, над блоком нарушений

## 4. Явное позиционирование uz-cyrl + ru — `сделано частично`
В ходе разбора рынка не нашёл ни одного конкурента, целящегося именно в
связку узбекский-кириллица + русский. Открытая ниша.

- Описание бота (`setMyDescription`) можно усилить акцентом на это
- README уже описывает локализацию как основную фичу, а не довесок

## 5. Платный тариф (freemium + PRO) — `готово`
Реализовано целиком: freemium-порог по модели Combot, выделенная Groq-квота,
капча/антирейд как PRO-фичи, оплата через Telegram Stars.

- `plan: "free" | "pro"`, `planExpiresAt` в настройках группы (`lib/billing/plan.ts`)
- **Freemium-порог**: `FREE_TIER_MAX_MEMBERS = 200` (тот же ориентир, что у
  Combot) — группы до 200 участников получают капчу/антирейд бесплатно как
  грейс-период; больше — нужен PRO. Базовая модерация (мат/спам) бесплатна
  всегда, независимо от размера — это принципиально не паяуоллим
- **Выделенная Groq-квота**: `lib/moderation/groq.ts` — RPM/RPD/TPM/TPD бюджеты
  разделены на пул `free` и пул `pro`, чтобы всплеск бесплатных групп не мог
  исчерпать квоту у платящих (сейчас условный сплит 17/8 RPM, легко подкрутить)
- **Капча + антирейд как PRO-фичи**: показывается PRO-бейдж и подсказка в
  Mini App, если группа не подходит по размеру/подписке; включение через
  API/команду отбивается 402, если не положено
- **Антирейд**: `checkRaid()` в `lib/moderation/flood.ts` — N вступлений за
  короткое окно принудительно включают капчу для всех вступающих в этот
  момент, даже если обычная капча выключена
- **Оплата — Telegram Stars** (`lib/telegram/payments.ts`), нативная
  30-дневная подписка через `createInvoiceLink` с `subscription_period`
  (это единственный метод API, который поддерживает recurring — `sendInvoice`
  не умеет). Команда `/upgrade` в чате, кнопка «Оформить PRO» в Mini App через
  `Telegram.WebApp.openInvoice()`. Цена — 349 Stars (~$5/мес, тот же ориентир,
  что и у Combot)
- Обработка `pre_checkout_query` (всегда ok, отвечаем в течение 10 сек) и
  `successful_payment` — активирует `plan: "pro"` по `subscription_expiration_date`
  из платежа, шлёт админам подтверждение
- **Не протестировано вживую** — реальный платёж через Stars можно проверить
  только внутри настоящего Telegram-клиента, локально это не симулируется

### Отраслевые пресеты словаря — тоже сделано попутно
`lib/moderation/presets.ts` — стартовые наборы скам-фраз (не мат) под нишу:
agro, ecommerce, edtech, finance. Команда `/preset <ключ>` и кнопки в Mini App
добавляют слова поверх уже имеющихся у группы, не заменяя их. Это черновые
наборы для ревью админом, не исчерпывающий список — как и с базовым
словарём мата, качество важнее охвата.

## 6. Улучшения админ-панелей (Mini App) — `план от 2026-08-31`

Разбор двух поверхностей: `app/group/[groupId]/*` (владелец группы) и
`app/owner/*` (владелец бота), против лучших практик (Combot/Rose —
dashboard-first и аналитика как retention-драйвер; Discord AutoMod /
Perspective — очередь ревью и объяснимый скоринг; Stripe/Linear — аудит-лог
с актором+диффом, сегментированные рассылки, feature-флаги с раскаткой).
Держим принцип TZ §15.1: не «простыня» настроек — заголовки секций поверх
существующих тумблеров, без вложенных подменю.

### 6.1 Сначала — баги и недоделки в текущем коде

- **`proFeaturesEligible` захардкожен `true`** — `готово 2026-09-03`.
  Было: `route.ts` GET отдавал `memberCount: null, proFeaturesEligible: true`
  константами, PATCH не возвращал поля вовсе (`GroupProvider` сбрасывал в
  `true` через `?? true`), PATCH-гейт использовал `isProActive` вместо
  `canUseProFeature(settings, memberCount)`. Итог: PRO-бейджи/`ProFeatureHint`
  никогда не видны, и группа ≤200 участников получала отказ PATCH хотя
  `/captcha on` в чате у неё работает.
  Сделано: GET и PATCH считают `getCachedMemberCount` + `canUseProFeature`,
  возвращают `memberCount` + `proFeaturesEligible` оба; гейт переведён на
  `canUseProFeature`. Плюс: отклонённые gated-ключи теперь **вырезаются** из
  патча перед `updateGroupSettings` (как это уже делают чат-команды через
  `requireProFeature`) — закрыт обход по `federationEnabled`, который
  `federation.ts` берёт из хранилища и не перепроверяет по размеру.
  Не сделано (отдельный шаг): PATCH всё ещё не возвращает `missingPermissions`,
  поэтому `GroupProvider` затирает его в `[]` после любого тумблера до
  следующего refresh — баг был и до этого, чинить на клиенте.
- **Захардкоженный русский мимо `t()`**: вся `app/group/[groupId]/owner/page.tsx`,
  вся `app/owner/tools/page.tsx`, `components/BottomNav.tsx:15` («Управление»),
  `components/JournalItem.tsx:22` (`toLocaleString("ru-RU")` — uz-юзеры видят
  ru-форматирование), `resolveErrorText` в tools.
- **`owner/overview/route.ts` — O(все группы) × 3 Redis-чтения** в одном
  `Promise.all`, без курсора/лимита. Промежуточно: курсор + капнутая страница
  + агрегат `bot:stats:{date}` для верхних плиток. Совсем — PG-роллап (TZ §11.3-14).
- ~~**`GlobalBanEntry.bannedBy`** хранится, но `owner/bans/page.tsx` не рендерит~~
  — `готово 2026-09-03`: рендерится строкой «актор {id}» под датой.
- **Журнал**: жёсткий потолок 50/300, нет пагинации/фильтра/поиска/разреза по
  юзеру. TZ §10.2 предусматривает даже `?limit=` — не проброшен.

### 6.4 Сквозное (обе панели)

- Аудит-лог на каждое мутирующее действие (актор, действие, цель, было→стало,
  время) — ограниченный Redis-list на скоуп. Фундамент для отмены и подотчётности.
  Сделано для owner-скоупа (`lib/db/auditLog.ts`, §6.5 п.4); для группового
  скоупа (мультиадминские группы, §6.2) — ещё нет, паттерн переиспользуем.
- Пуши админам через бота (инфры не надо): бот потерял право, обнаружен рейд,
  кончилась квота, пришёл/сорвался платёж, первая волна спама в новой группе.
- Deep links: уведомление бота → конкретный экран Mini App через `startapp`.
- Полный i18n: все строки через `ru.json`/`uz.json`, убрать захардкоженный `ru-RU`.
- Проход по a11y: `<label htmlFor>`, focus-visible, тач-цели ≥44px, `aria-live`
  на тостах, контраст (светлая тема зафиксирована — достижимо).
- Консистентность: `BottomNav`/`OwnerNav` — почти дубликаты, вынести `<TabBar>`;
  `owner/page.tsx` и `tools/page.tsx` не используют общий паттерн тостов.

### 6.6 Что взять у ботов-«чистильщиков» — `разбор от 2026-08-31`

Референс от владельца: **@one_minute_post_bot** — нишевый бот для админов
каналов с комментариями. Публичной документации нет, только слоган: «Сними
с себя админскую рутину: анти-спам, чистка подписчиков, отложенный постинг»
(поддержка @dadkakdad). Из него релевантны две вещи: анти-спам в
комментариях (у нас уже сильнее) и **«чистка подписчиков»** — удаление
«мёртвых душ» из аудитории. Отложенный постинг — не наш продукт, мимо.

Категория «чистильщиков» распадается на два разных класса — мы почти
полностью в первом, второго нет вообще:

#### A. Чистота чата (сервисные сообщения, команды, свои уведомления)

Кто: Rose (`/cleanservice`), GroupHelp, ChatKeeper, @cleanerchatbot.

Что у Rose удаляется по типам: `join`, `leave`, `pin`, `photo`, `title`,
`videochat`, `other` (платежи, proximity, webapp, буст, розыгрыш), `all` —
плюс отдельно «удалять команды» и «удалять свои сообщения бота».

**Что есть у нас:** `deleteServiceMessages` (`bot.ts:322-430`) удаляет
**только** `new_chat_members` и `left_chat_member`. Всё.

**Добавить (дёшево, чистый Bot API, наш стиль — один тумблер + один пикер):**
- Расширить `deleteServiceMessages` на остальные типы: `pinned_message`,
  `new_chat_photo`/`delete_chat_photo`, `new_chat_title`,
  `message_auto_delete_timer_changed`, `video_chat_*`,
  `proximity_alert_triggered`, `boost_added`, `giveaway_created/completed`,
  `successful_payment`, `write_access_allowed`. Один тумблер «чистить все
  служебные» + опционально свёрнутый список типов (как у Rose
  `join leave pin`), не отдельные тумблеры на каждый.
- **Авто-удаление своих уведомлений модерации по таймеру** («one minute» из
  названия): сообщения из `notifyChat` (`violations.ts` — «@user забанен за
  спам», warn/mute/CAS-нотисы) удаляются через N секунд (пикер 30/60/300/off,
  дефолт — как сейчас, не удалять). Serverless-совместимо: ленивый sweep по
  Redis-ключу с TTL, как уже сделано для капчи (`captcha.ts`), либо
  `message_auto_delete` через сам Telegram где применимо.
- **Удаление команд участников** (`/help`, `/rules`, …) и своих ответов на
  них через несколько секунд — тумблер «убирать команды из чата».
- **Удаление авто-репостов привязанного канала** в чат обсуждения
  (`is_automatic_forward`) — частый запрос, один тумблер.

#### B. Чистка аудитории — «мёртвые души» (у нас нет)

Кто: @crosser_bot, @ukinti_bot, Keep (keepbot.io), GladOS. Удаляют:
удалённые аккаунты, накрученных ботов, неактивных (не заходили >неделя /
>месяц), по дате вступления, по RTL-символам в имени, недавно вступивших
за X часов; с превью списка, выбором % и отменой на любом шаге.

**Ключевое ограничение:** эти боты работают через **userbot (MTProto)** —
Bot API не отдаёт полный список участников группы (>200) и «последний
онлайн». Мы — только Bot API (grammY webhook на Vercel). Полный аналог
Crosser нам недоступен без отдельного MTProto-воркера (архитектурный сдвиг,
инфра, риск бана аккаунта — **не делать на старте**).

**Что реально сделать на Bot API (MVP «санитарной чистки»):**
- **Пассивный сбор «мёртвых душ»:** мы уже кешируем авторов сообщений
  (`messageAuthors.ts`). Отмечать в отдельном set ID, которые:
  (а) при `chat_member`-апдейте или в сообщении приходят как удалённый
  аккаунт (`first_name` пустой/«Deleted Account», без username);
  (б) не написали ни одного сообщения за N дней, хотя раньше писали
  (сравнение с окном активности из stats). Это подмножество, не полный
  роспись — Bot API даёт ровно тех, кого бот «видел».
- Экран в панели группы «Неактивные / удалённые» → превью списка (id +
  последняя активность) → «удалить всех» / «удалить удалённые аккаунты»
  (кик = `banChatMember` + сразу `unbanChatMember`, чтобы могли вернуться),
  с подтверждением и лимитом батча (rate-limit Telegram, как в
  `broadcast.ts`). PRO-фича по духу (behavioral, не core safety — §15.1).
- **Немедленный кик удалённых аккаунтов на входе/при сообщении** —
  отдельный тумблер «не пускать удалённые аккаунты» (дёшево, ловится прямо
  в вебхуке, без сборки списка).
- Метрика в статистике: «удалённых аккаунтов в группе (замечено ботом)».
